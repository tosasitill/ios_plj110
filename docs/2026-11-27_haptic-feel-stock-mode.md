# 模式 3（库存波形）手感四项改进：分级力度 / 去死区 / 包络跟随 / 快速重武装

## 背景

模式 3（`x9_haptic=3`，默认）把 iOS 的 48 kHz PCM 只当事件提示：onset 后播一发
固定的满幅库存 tap。手感"散"的代码级成因（调研结论 A1–A4）：

- **A1 力度全丢**：HAL START 写死 intensity=1000，worker 恒满幅缩放；
  selection / medium / heavy / 键盘全是同一发满幅 tap。
- **A2 连续事件被摧毁**：onset 后持续超阈值不再 re-arm，CoreHaptics
  continuous 只剩开头一发；多脉冲 pattern 同理被压扁。
- **A3 每发后退役整条流**：stock 波形播完走 draining → `stop_locked` 清
  RUNNING 且 generation++，HAL 下一次 write 撞 EPIPE 后只能等 500 tick
  轮询重开，死区最长约 500 ms，落入的反馈静默丢失（连打丢键）。
- **A4 播放/draining 期间的 onset 被吞**：<~20 ms 间隔的双击第二下会丢。

已排除：硬件 auto-brake 是开着的（BRK_EN 与原厂一致），本次未动刹车；
未改 `/dev/x9-haptic` 包协议与状态 ABI，未动模式 0–2 的 PCM 透传路径。

## 架构

模式 3 的事件逻辑抽成纯头文件引擎
`x9/kernel/src/bsd/dev/x9_haptic_stock.h`（与 `x9_haptic_convert.h` 同一
惯例：无内核依赖，主机测试直接跑生产代码）。内核侧
`sweet_x9_haptic.c` 只做播放胶水：write 路径逐样本喂引擎，worker 按引擎
事件启动/循环/排队库存波形。

总开关：boot arg `x9_haptic_feel`（位掩码，默认 15 = 全开）：

| bit | 值 | 项目 |
| --- | --- | --- |
| 0 | 1 | GRADE 分级力度 |
| 1 | 2 | HOLD 流末保活 |
| 2 | 4 | ENV 包络跟随 |
| 3 | 8 | QUEUE 快速重武装 + 排队 + 尾巴守卫 |

**回退**：`x9_haptic_feel=0` 即逐项恢复旧行为（固定满幅、播完退役、无
buzz、1 ms 武装且播放中吞 onset）；也可只关单个 bit 做 A/B。

## 1. 分级力度（GRADE）

- onset 后开 2 ms（96 样本）峰值捕获窗，用窗内 PCM 峰值定强度——不再用
  START 的固定 intensity。捕获窗只引入 2 ms 决策延迟，远小于既有 20 ms
  预填。
- 峰值经平方根（感知）曲线映射为期望输出峰值（0..127）：
  32767→127、8192→63、2048→31、1024→22。线性映射会把 iOS 强度下半区
  压成一团，平方根曲线让轻档之间仍有区别、满档仍是满档。
- 按期望输出峰值选波：<40 走轻档，其余走标准 tap。轻档波形
  `x9_stock_tap_light` 是新搬的 ColorOS `aw8697_stepable_regulate_RTP_105`
  （步进调节 tick，原生峰值仅 12/127），用与既有波形相同的 32-tap Hamming
  sinc + ×2 抽取重采样（方法对拍验证：能逐样本复现已入库的
  `x9_stock_tap`）。播放时按波形原生峰值反算 intensity，使其实际输出峰值
  落在曲线上——轻波形被放大、标准 tap 被缩放，输出峰值只由 PCM 峰值决定。
- 效果预期：selection/键盘类轻事件第一次有了"轻"的落点，impact 类保持
  满幅，中间档连续可分。EFFECT ioctl 的场景路径不变（仍按场景固定波形 +
  调用方 intensity）。

## 2. 去死区（HOLD）

- mode 3 流排空（FIFO 空 + 芯片 standby 已证实）后不再 `stop_locked`
  退役：保留 RUNNING 与 generation，进入 200 ms 保活（与 PCM 路径的静音
  保活同一窗口）。后续 HAL 包直接续流，不再 EPIPE、不再等 500 tick 重开。
- 保活到期未用则按原路径退役；显式 START 或新场景立即接管保活
  （START 先走一次退役清理）。`completed_streams` 仍逐次计已完成的硬件
  运行；STOP/close/fault 的退役语义不变。HAL 侧无需改动。

## 3. 连续事件包络跟随（ENV）

- PCM 持续 hot 超过 30 ms 后，引擎进入包络跟随：库存 buzz 波形循环播放，
  幅度由 PCM 包络（峰值跟踪，快攻 + ~5 ms 释放）调制，直到 PCM 跌破阈值
  持续 5 ms 才结束并走 draining。onset 处已打出的分级 tap 保留，buzz 是
  其后接上的"身体"，不是替代。
- sustain 计时按事件跨度算：只有 ≥1 ms 的真静默才清零。iOS 连续事件是
  包络正弦，过零点附近每半周期都会跌破 512 几十微秒，数"连续超阈值
  样本"永远攒不到 30 ms——这是激活此路径时一并修掉的引擎缺陷。
- buzz 场景豁免 1 s 场景上限（PCM 流本身就是它的边界；HAL 停写另有
  100 ms park/fail 保护）；ring 预填深度限 40 ms，避免包络变化在队列里
  等 ~340 ms。

## 4. re-arm 放宽 + 排队一发（QUEUE）

- 武装门限 1 ms → 0.25 ms（12 样本），但带峰值迟滞：静默必须跌破
  上一事件峰值的 1/16（钳在 96..512）才计数。平坦的 512 电平下，衰减中的
  ~173 Hz 脉冲在自身过零点就会重新武装（周期幅值降到 ~1500 时其
  sub-512 凹陷已超过 0.25 ms）并打自己一发——迟滞要求信号先落到上一发
  的十六分之一，尾巴凹陷达不到。
- 播放/draining 期间捕获完成的 onset 可排队一发：worker 在当前场景填完
  的瞬间提升它，无缝接在其后（双击第二下不再丢）。队列满（已有待播）
  时多余 onset 丢弃并计数（`stock.dropped`）。
- 尾巴守卫：候选峰值不到上一事件峰值的 1/4、且距上一事件 <20 ms 的，
  判为同一脉冲的衰减尾巴而抑制（`stock.tail_dropped`）。每个被判定事件
  （打出/排队/丢弃/抑制）都更新参考峰值与迟滞电平，所以被抑制脉冲自己
  的尾巴也按它判定。真实双击两发峰值相近、不受影响；20 ms 之后的轻
  事件按时间条款放行。
- 已知取舍：重击后 20 ms 内跟一个真实的极轻事件会被抑制——与"尾巴"
  在 PCM 上不可区分，取舍偏向不重复打。峰值 <~700 的极轻事件其自身
  尾巴仍可能以极低强度（level ≤18）多打一发，物理上被首发的余振掩盖。

## 验证

- 主机行为测试 `x9/haptic/test_haptic_stock.py`（harness 编译生产头文件
  + 已入库波形，合成 PCM 断言）：轻/中/重 onset 的选波与输出峰值、强度
  单调性、legacy 等价（固定满幅、1 ms 武装）、hold 到期/取消、250 ms
  连续事件的 tap+buzz 开关时序、包络跟随 6000→24000 幅值台阶、双击排队
  不丢、连打六发不丢、队列满恰丢一发、尾巴抑制与 40 ms 后对照放行、
  0.5 ms 间隔在 QUEUE 下重武装。共 55 项断言全过。
- 基带全套测试无回归（仅剩 test_call_owner_boundary、
  test_sms_pdu_class 两项预存 SDK 环境错误，与未改 main 相同）。
- 内核整树构建通过：候选 `haptic-feel-check2-20261127`，boot.img 15,392,768 B（仅作编译验证，未 stage、未刷机）。

## 仍需上机调参（不在本轮范围）

- **首发延迟**：20 ms 预填与 GO/boost 启动未动，实测延迟构成以日志为准。
- **f0 实测**：173 Hz 仍是默认值，未做机械共振实测（不要读 `f0_save`，
  有重启前科）。
- **分级边界与曲线**：`X9_HS_LIGHT_MAX_LEVEL=40` 与平方根曲线是首版
  猜测值，selection 与键盘在真机上是否分得开、轻波形放大后是否失真，
  需要手感 A/B 后微调（改引擎头常量即可，测试断言跟着改）。
- **buzz 的音色**：库存 buzz 循环点在整波首尾，包络台阶的平滑度与
  40 ms 预填的跟随感需实机听感确认。
- **保活与 HAL 时序**：200 ms 保活覆盖连打间隔的假设（键盘连打、游戏
  连发）需在真实 mediaserverd 节奏下验证；若 HAL 在保活期内 StopIO，
  STOP 路径退役语义已保持不变。
