# X9 baseband bridge (iOS side)

`qcom/` is an import of UniXNU/QcomBaseband (BSD-2-Clause, HoshinoYumeka / chiba233; upstream commit recorded in
`qcom/UPSTREAM.json`). Only `baseband/` (AppleBaseband IOKit services, QMUX/QRTR bridge, SAHARA stub, PDP interfaces, eSIM Tape)
is used. `ipa/` and `platform/coachz` (Qualcomm IPA/GSI) are not copied: the X9 modem is MediaTek, its data plane is DPMAIF.

Status (2026-11-09): the MT6993 CCCI file/RPC service reaches HS2/READY, SIM READY and network registration in `~/139.txt`.
NV partitions are read-only; modem writes go into a 128 MiB volatile overlay. Reboot discards those writes.

With `x9_bb=1`, `X9Baseband.cpp` prepares the AppleIPAppender/PDP-manager services synchronously before launchd;
the full bridge, network interfaces and transport worker still start after physical HS2. This avoids the observed
20H392 ApplePDPHelper null singleton when CommCenter starts before the MD finishes booting. It adapts the imported iOS bridge to a local
QRTR/QMI stub: six services are announced and requests return `QMI_ERR_NOT_SUPPORTED` while logging their headers.
This is a discovery build, not working iOS cellular support. The PDP/DPMAIF data plane is not implemented.

Local changes to the imported bridge: public mbuf KPI include (see `qcom/pdp-mbuf-kpi.patch`), X9 `x9_bb` enable switch,
bounded handshake diagnostics, and pre-launchd helper publication with a reusable traffic-gate lock.
The upstream README describes Coachz/iOS 17, not X9/iOS 16 results. With the explicit `x9_bb=1` boot token,
the boot packager includes the original D22AP discovery metadata: `/baseband` class 3, compatible `baseband,n41`,
device type `baseband`, and `/product/baseband-chipset` `mav17`. This does not describe Apple GPIO/MMIO or change
the X9 hardware and iPhone10,3 compatibility identities. Unlike J121AP, the original D22AP node has no eUICC chip ID.
The reference's original Apple firmware mounts are adapted for Mav17 as described below. Its patched
21H461 postponement-ticket compatibility executable is deliberately not imported: both its version and
its machine-code changes conflict with this project's original-20H392-byte requirement.

## Reference coverage and remaining hardware work

The comparison input is QcomBaseband `dd0199cf3300764ed52b23f4a47761f91fab21a2`, particularly
`baseband/*` and `platform/coachz/patches/coachz-prelink-baseband.patch`. The portable bridge has no
missing functional delta against that revision; X9 additionally has early helpers and bounded diagnostics.

| Reference feature | X9 implementation / limitation |
| --- | --- |
| AppleBaseband board/PCI/user clients, 18 channels | Imported and published, 22/22 services in `145.txt`; actual PCI requests still absent |
| QMUX/QRTR client allocation, CTL and buffered async reads | Imported `coachz_bb_qmux.h`, `coachz_bb_channels.h`, `coachz_baseband.cpp` |
| SAHARA, boot image exchange, BSP | Imported `coachz_bb_sahara.h`; no real request in `145.txt`; Apple assets never boot the MTK MD |
| PRI/GRI, FileTransferStatus, activation identity | Already in `coachz_baseband.cpp`; require real modem replies / SIM reads, not invented identity |
| PDP family state, traffic gate, protocol plumbers | Imported `coachz_bb_pdp.*`; four interfaces are not proof of a working data path |
| WDS/QOS binding, DPM/WDA setup | Portable `coachz_bb_data.h` present; Qualcomm embedded endpoint mapping is not a DPMAIF implementation |
| VINYL Tape/UIM eSIM APDUs/cache/session cleanup | Imported `coachz_bb_esim.h`; D22AP metadata deliberately advertises no invented eUICC |
| Board boot / filesystem / calibration | MT6993 CCCI/FSD/RPC implementation, physical HS2/READY and registration observed; NV preserved |
| DT and cellular launch job | D22AP class3/n41/mav17 implemented; original CommCenter already runs in `145.txt` |
| Original Apple firmware delivery and paths | `baseband_firmware.py` + `x9_baseband_firmware.inc`, compiled in `rev252eq-md`; hardware validation pending |
| ABM/BB/CommCenter logd private options | Create-if-missing boot integration; existing logging preferences preserved; local logs only |
| Qualcomm IPA v4.2/GSI packet hooks | Not portable to MT6993; real DPMAIF TX/RX/DMA ownership remains missing |
| Genuine DMS/NAS/UIM/WDS/QOS/VOICE requests | Board AT/CCCI-to-QMI translation remains missing; current six servers return error94, not fabricated success |
| Patched CommCenter and BBTicket/postponement policy | Not applied; no valid Apple ticket is generated by this bridge |

## Original Mav17 firmware input and boot-time view

Extract the manifest-selected D22AP member from the local **original** 20H392 IPSW:

```sh
python3 -I x9/tools/baseband_firmware.py --ipsw /path/to/original-20H392.ipsw
python3 -I x9/build/build.py all --name x9-rev252eq-md \
  --boot-config .local/x9/modem/boot-rev252el-md.json
```

The first command checks build/device selection and ZIP CRCs and stores the original
`Firmware/Mav17-9.00.02.Release.bbfw`, manifest, source metadata and compressed pack under
`.local/x9/baseband/`. Normal builds package that input automatically. `baseband_firmware` in
`x9/build/local.json` can select an explicit local `.bbfw`; a missing explicit input fails the build.
With no default input a clean checkout emits an empty stub and reports it, rather than embedding stale data.
Generated `.incbin` data and Apple assets are ignored by git.

On the owner's next manual boot, before launchd and only with `x9_bb=1`, writable native X9 root and
64-bit PID1, the kernel verifies the packed digest and every decompressed member, then creates missing
0644 root:wheel files in `/private/var/x9/baseband/Mav17`. Matching files are kept, different files/symlinks
are rejected without replacement; temporary files are synced and hard-linked into place without truncation.
The 12 original assets include the original **empty** `Options.plist`. Maximum transient decompression
allocation is about 57 MiB, not a permanent second modem firmware allocation.

Read-only bindfs leaf mounts expose the same original bytes at:

* `/usr/standalone/firmware/Baseband/Mav17`
* `/private/preboot/<UPPERCASE_BOOT_MANIFEST_HASH>/usr/local/standalone/firmware/Baseband/Mav17`

Unlike Coachz's sealed-root integration, the writable HFS root needs no parent union overlay. Cryptex and
dyld-cache directories are never covered. All 12 visible assets are checked after each mount. The pre-exec
bindfs entitlement exception is limited to the current kernel mount caller thread, PID1/native X9 root,
`x9_bb=1`, and the fixed verified source; other mounts still need their original entitlement.
This follows UniXNU `ae687009`'s `zzy-native-gpu-addon-mount.patch` but does not introduce its global
authorization flag, force-root ABI change, or unrelated GPU overlays.

`x9_bb_firmware=0` disables installation/mounts; `x9_bb_logging=0` disables creation of private logd
subsystem options. Existing logging preferences are not replaced. Installation errors are non-fatal and
reported with `X9 BBFW`; neither a generated manifest hash nor mounted files is a BBTicket,
personalization signature, physical modem boot, or evidence that ABM completed startup.

The built candidate must be started manually. Verify `rev252eq-md fs128-bb-mav17fw-v1`,
`X9 BBFW: original 20H392 Mav17 files 12 ... standalone errno=0 personalized errno=0`, then physical
HS2/READY and **real** protocol/PCI/SAHARA/QMUX requests. `145.txt` validates the older DT/helpers,
not these new firmware mounts. If requests remain zero, return to the original iOS16 ABM start-group /
controller selection instead of changing the already-tested CCIF/FS or pretending unsupported QMI succeeded.

`~/140.txt` lacks both the 128 MiB pool startup line and `x9_bb=1`; it repeats `~/138.txt`'s `FD27_003` write failure and
`lid_error_handle.c:259` assertion. It cannot validate the new bridge. `rev252el-md` adds a compiled startup marker plus
pool/node/handle failure counters to identify the executing image before changing another protocol variable.
